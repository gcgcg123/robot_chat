# 第二階段：ESP 到貨後韌體與真機 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans after Phase 1 acceptance and explicit hardware authorization. Steps use checkbox (`- [ ]`) syntax. 本文件不預設商品 revision、COM 埠、GPIO、Flash offset 或可直接燒錄的映像。

**Goal:** 在第一階段 PC pipeline 已驗收後，讓 DNESP32S3＋2.4 吋 LCD 成為真正的半雙工語音終端：收音、身份辨識、播放 TTS、顯示字幕／角色，並通過 MQTT＋UDP。

**Architecture:** ESP 僅負責收音／編碼、播放／緩衝、LCD、按鍵和網路；laptop 保持 ASR、聲紋、分析、RAG、DeepSeek、TTS 及資料保存。韌體 adapter 依協議能力協商將同一套 turn events 映射到 Xiaozhi 相容 gateway，不把上游範例當成使用者硬體已驗證設定。

**Spec:** [總覽](C:/Users/gcgcg/OneDrive/Desktop/IoT_group5/project_place/docs/superpowers/plans/2026-09-14-two-stage-implementation.md)、[語音／螢幕規格](C:/Users/gcgcg/OneDrive/Desktop/IoT_group5/project_place/docs/superpowers/specs/2026-09-13-esp-voice-display-design.md)。

## 進場條件與安全停點

- Phase 1 自動測試、PC 端到端、資料備份／回復及協議 fixtures 已保存；沒有 Phase 1 不進行真機除錯。
- 使用者明確通知「ESP 已到貨，可以接入」；首次 USB 連接由使用者在場，任何擦除／刷機前先取得當次確認。
- 不猜測硬體。先讀 PCB 絲印、商品原理圖／revision、Flash／PSRAM、LCD controller／解析度／觸控、codec、mic／speaker、供電、按鍵、USB-UART；以實物／文件證據填 `docs/hardware/DEVICE_INVENTORY.md`。
- 保留原韌體讀取／回復方式和原始 binary hash；不得在不明確的 port、partition、GPIO 上執行 erase／flash。相機不是本專案必要元件，無相機硬體要在板級設定中關閉／條件初始化。
- 參考來源 commit `236deb266a88ade000cc85e20c0ccacc765e0ce3` 的 `main/boards/alientek/atk-dnesp32s3/` 僅作比對。它是 ST7789 320×240、ES8388，I2S 輸入／輸出 24 kHz；後端仍是 ASR 16 kHz。來源無條件初始化相機，不能盲目套用。
- 真機測試採半雙工、耳機／喇叭音量由低開始；未驗證 AEC、喚醒、全雙工、活體聲紋、觸控或相機，不在演示中宣稱已支持。

## P2-01：盤點、工具鏈與回復

**Files:** Create `docs/hardware/DEVICE_INVENTORY.md`、`docs/hardware/RECOVERY.md`、`firmware/README.md`、`scripts/inspect-esp.ps1`、`tests/hardware/test_inventory.py`；Modify `docs/PHASE1_HANDOFF.md` only to link evidence.

- [ ] 拍／讀板上型號與 revision，記錄 USB 裝置名稱、實測電壓與可用記憶體；Windows 裝置管理員查實際 COM port，命令輸出保存到 inventory。COM 變動不寫死到 source。
- [ ] 安裝／核對與上游 release 相符的 ESP-IDF、Python、串口工具；固定 toolchain manifest 和來源 commit。若現有開源資料包含 camera default，先建立 no-camera 配置及編譯測試。
- [ ] 以 read-only／合法工具讀出版本、partition table 和可回復映像；驗證 backup hash。任何讀取失敗先停，不以空檔案當備份。
- [ ] 單元測試只驗 inventory schema；命令測試使用 fake serial output。尚未取得所有硬體證據時，P2-01 保持 blocked，不能進 P2-02。

## P2-02：板級 bring-up 與 LCD／音訊

**Files:** Create／Modify only after P2-01: `firmware/main/board_config.*`、`firmware/main/display_adapter.*`、`firmware/main/audio_adapter.*`、`firmware/main/enrollment_ui.*`、`firmware/assets/ASSET_LICENSES.md`；Test `tests/hardware/test_firmware_contract.py` and on-device checklist.

- [ ] 從已核實板級檔案選 target；先只燒最小 recovery／hello build，測 boot、reset、背光、LCD 色條／繁中測字、按鍵，並記錄實測解析度與方向。尺寸相同不代表 ST7789／相同 GPIO。
- [ ] 接通 mic／speaker／codec 後分開測 I2S input／output、24 kHz（若實物不同以 inventory 為準）、音量、削波、左右聲道；建立短錄音 hash／波形摘要，不保存未同意的原始語音。
- [ ] 韌體 PCM／Opus adapter 對齊 hello 能力；後端每輪仍轉 16 kHz mono 給 ASR。建立 frame sequence、buffer 水位、underrun／overrun、錯誤碼。
- [ ] 韌體測試包括斷電／重啟、低記憶體、錯誤 LCD／codec 初始化；失敗回到上一個可開機映像，不能強行進入網路整合。

## P2-03：MQTT＋UDP gateway

**Files:** Modify `services/device_gateway/xiaozhi_adapter.py`、`services/device_gateway/mqtt_udp.py`；Create `firmware/main/protocol_client.*`、`configs/device/<revision>.json`、`tests/device_gateway/test_real_fixtures.py`、`docs/hardware/PROTOCOL_CAPTURE.md`.

- [ ] 先對照上游 MQTT／UDP／WebSocket 文件及實際 server gateway 程式，確認 session、nonce、裝置 token、序號、音訊 frame、重連與加密；不可把 PC WebSocket 當真機協議。
- [ ] localhost／受控 LAN broker 建立獨立 device credential；MQTT 僅載 hello、狀態、控制／註冊命令，UDP 承載協商後音訊；拒絕錯 session、duplicate、stale、亂序和越界包。禁止把管理員 DeepSeek key 放進 ESP。
- [ ] 由 firmware 回報 `capabilities`（sample rate、codec、LCD、playback_ack、enrollment_v1），後端拒絕不支持組合並保留錯誤；沒有 ACK 顯示 `sent_unconfirmed`，不能虛報 completed。
- [ ] 用 loopback／抓包 fixtures 驗證真實 payload、丟包／重排／斷線／重連／重複命令；成功後才將相同測試帶到實板。網路服務先綁明確介面，LAN 開放需另行確認防火牆／TLS。

## P2-04：註冊、完整回覆與畫面

**Files:** Modify `firmware/main/application.*`、`firmware/main/display_adapter.*`、`firmware/main/audio_adapter.*`、`services/enrollment/service.py`、`services/device_gateway/xiaozhi_adapter.py`; Test `tests/hardware/test_turn_events.py` and manual matrix.

- [ ] ESP hello 後接受帶 `enrollment_id` 的 ready／ACK；語音提示播放完成才收 sample；sample_id／prompt_id／session／turn 去重。硬體樣本補錄／重新校準後才把 PC 註冊結果當候選，不能直接假定 mic 差異不影響門檻。
- [ ] 顯示狀態 idle／listening／thinking／speaking／enrollment／interrupted／disconnected／error；字幕按 sentence sequence，320×240 長句分行／分頁。robot_expression 白名單 neutral、listening、thinking、speaking、caring、happy、error；缺資源回 neutral。
- [ ] 音訊播放佇列以 segment／sequence 排序；按鈕 abort 立即停止本地音訊，再通知後端取消，舊 turn 的遲到音訊／字幕／表情全部丟棄。正常完成與 abort 不共用無條件清空流程。
- [ ] 若韌體具 playback started／completed ACK，回傳實際音量／buffer／錯誤；若無 ACK，Dashboard 清楚顯示未確認，不用「伺服器已發送」替代「使用者已聽到」。
- [ ] 真機測普通話／繁中字幕、英文混合及長句；粵語語音另行確認，繁中字幕不作粵語證明。圖片／字體／動畫逐項檢查 license、Flash／PSRAM 及幀率，不移植大 Live2D。

## P2-05：穩定、校準與交付

**Files:** Create `docs/hardware/TEST_MATRIX.md`、`docs/hardware/DEMO_RUNBOOK.md`、`scripts/firmware-build.ps1`、`scripts/firmware-flash.ps1` (must require explicit `-ComPort` and confirmation)；Modify `docs/STARTUP_GUIDE.md` with separate ESP steps.

- [ ] 真 mic 由至少兩位已同意組員補錄獨立 enrollment／verification／留出測試；重新計算 threshold／top-two margin，記錄 false accept／reject／unknown／ambiguous、距離／噪音／方位，不把 PC 數據直接套用。
- [ ] 測冷啟／暖機／每段延遲、連續十輪、長時間運行、Wi-Fi 斷線／重連、MQTT broker 暫停、UDP 丟包／亂序、播放 underrun、LCD 重繪、取消／下一位說話者；故障時身份／私密記憶必須隔離。
- [ ] `firmware-flash.ps1` 只接受從 inventory 實際填入的 COM 與經核對的映像 hash；先列出目標裝置／版本／回復方式並要求互動確認，絕不自動 erase。
- [ ] 展示順序：開機／LCD→連線→A註冊→A負面心情→關懷回覆→字幕／播放 ACK→A/B輪換→未知者→中斷→斷線／重連→Dashboard查詢。錄影或截圖去除 API key、完整個資及原始錄音。
- [ ] 通過後更新 `docs/IMPLEMENTATION_STATUS.md`：只寫實際板 revision、韌體 commit／hash、工具鏈、測試矩陣與已知限制；保留回復指令及未支持項（相機、AEC、全雙工、活體）。
