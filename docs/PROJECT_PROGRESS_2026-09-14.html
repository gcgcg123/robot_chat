RAG 責任邊界：小智概念與本專案設計

分類保留自小智概念本專案情感機器人自訂設計
LLM 工具呼叫保留「由 LLM 決定是否呼叫檢索工具，再把結果放回上下文」的編排方向。P1 先以 process_text 明確編排；未來工具 schema、權限與取消由本專案控制，不讓文件內容觸發管理操作。
RAGFlow retrieval參考小智 search_from_ragflow.py 的 POST /api/v1/retrieval、dataset ids、最多五段 chunks。RAGFlowProvider 只作 optional adapter；endpoint/token 必須由環境配置，P1 預設不連外，RAGFlow 需另行部署。
三層資料隔離小智的 RAGFlow 與 memory provider 概念可作為外部知識／記憶的接入參考。我們另外定義 shared 共享知識、user:<id> 個人記憶、analysis 情緒／風險資料三層；owner、consent、approved 過濾先於相似度。
訓練與資料治理不直接複製小智的資料或模型權重。先以核准 txt/md 與虛構記憶建立 fixture；日後才加入 CPU embedding（如 BGE-small），記錄 revision、維度、hash、來源與刪除紀錄；聲紋與情緒模型另行校準。

本輪新增：RAG 與 UDP 設計

RAG 分層

  • shared：管理員核准的 UTF-8 txt/md；可供所有已授權對話使用。
  • user:<id>：個人記憶，只有聲紋 decision=accepted 且 memory consent 有效時可讀。
  • analysis：情緒／風險事件，供 Dashboard 查詢，不直接當作提示詞事實。
  • 檢索先做 owner／approved／active 篩選，再取 top-k；context 會標記為「不可信參考」，不能覆寫 system 規則或觸發管理操作。
  • 小智參考的 search_from_ragflow.py 已轉成 optional RAGFlowProvider（POST /api/v1/retrieval、最多 5 chunks）；RAGFlow 本身仍需另行部署。

UDP／MQTT／WebSocket 邊界

  • MQTT：裝置註冊、heartbeat、控制與能力協商，不承載正式音訊。
  • WebSocket：第一階段 PC 模擬器的互動事件、字幕、TTS segment、播放 ACK。
  • UDP：第二階段低延遲 PCM／Opus 音訊候選；P1 只完成 IOT1 frame、session 驗證、sequence 去重與 wrong-session 拒絕。
  • UDP loopback 通過只證明 adapter／封包規則，不能代表 DNESP32S3、Wi-Fi、codec 或防火牆已通過。
